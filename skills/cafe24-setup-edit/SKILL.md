# cafe24-setup-edit (세팅 위치 안내 → setup.js 미리보기 → 전문 전달)

## 개요

표준 스킨 몰은 화면 문구·링크·이미지·노출 여부 같은 몰별 값을 `setup.js` 한 파일에 모아 둔다. 사업부는 이 파일을 카페24 관리자의 스마트디자인 편집창에서 직접 고친다. 이 스킬은 사업부의 요청을 받아 다음을 한다.

1. 라이브 몰에서 지금의 `setup.js` 원문을 받는다.
2. 요청이 어느 설정(전역 변수와 키)에 해당하는지 찾는다.
3. 수정본을 브라우저 탭 안에서만 적용해 저장 전에 결과를 보여준다.
4. 바꿀 위치와 변경 후 파일 전문을 건넨다.

표준안의 세팅 위치는 세 곳이다. 요청이 어디에 해당하는지에 따라 처리가 갈린다(3단계).

| 세팅 위치 | 이 스킬이 하는 일 |
|---|---|
| `setup.js` | 수정 위치 안내 + 미리보기 + 변경 후 전문 |
| 카페24 관리자 | 관리자 메뉴 경로와 세팅 방법 안내 (관리자는 열지 않는다) |
| 훅 파일 `hook/hook-detail-early.html` (상세 접근 차단) | 바꿀 한 줄 안내 |
| 그 외 | "개발팀에 문의하세요." |

관리자·훅 항목의 목록과 경로는 [references/admin-and-hook.md](references/admin-and-hook.md)에 있다. 운영 매뉴얼(노션)을 요약한 것이다.

이 스킬은 **로컬 코드가 없는 환경(Claude Desktop 등)** 을 기준으로 한다. 모든 판단은 라이브 몰에서 받은 `setup.js` 원문과 화면에서 한다. `setup.js`의 주석이 곧 설정 설명서다. 각 전역 위에 용도, 키, 쓰는 화면이 적혀 있다.

**하드 경계**
- 몰 서버 상태를 절대 바꾸지 않는다. 관리자 로그인, 편집창 저장, FTP 업로드를 하지 않고 대신 해주겠다고 제안하지도 않는다. 미리보기는 내 브라우저 탭 안에만 있는 화면이다. "반영된 거냐"는 질문에는 "아직 반영되지 않았고, 건넨 전문을 편집창에 붙여넣고 저장해야 반영된다"고 답한다.
- 고치는 대상은 `setup.js`와 훅 파일의 차단 목록 한 줄뿐이다. 관리자 항목은 경로 안내만 한다. 셋 다 아니면 이유 한 줄과 **"개발팀에 문의하세요."** 로 끝낸다. 다른 파일을 고치거나 코드를 새로 짜는 안을 내놓지 않는다.

## 입력 (둘 다 필수)

1. **하고자 하는 일**: 예) "상단 띠배너 문구를 '오늘만 무료배송'으로 바꾸고 싶어요"
2. **반영하려는 몰의 URL**: 예) `https://cloop.co.kr/` 또는 개발 스킨 `https://cloop.cafe24.com/skin-skin49/`

둘 중 하나라도 없으면 **작업하지 않고** 빠진 항목을 요청하는 답만 하고 끝낸다. 몰 URL을 대화 맥락·추측·설정 파일에서 만들어내지 않는다. 다른 몰이나 다른 스킨을 집을 수 있다.

요청이 모호하면(어느 배너인지, 어떤 문구인지 불분명) 작업 전에 짧게 되묻는다.

## 절차

### 1. 라이브 setup.js 원문 받기

- 위치: URL 경로가 `/skin-skinN/`으로 시작하면 `<origin>/skin-skinN/setup.js`, 아니면 `<origin>/setup.js`. 캐시를 피하려고 `?x=<타임스탬프>`를 붙인다.
- **원문 그대로(raw)** 받아야 한다. 받는 수단은 아래 순서로 고른다.
  - 셸이 있으면 `curl -s "<setup.js URL>?x=$(date +%s)" -o <작업폴더>/setup.original.js`
  - 브라우저 도구(페이지에서 JS 실행 가능)가 있으면 몰 페이지를 연 뒤 `fetch('<경로>/setup.js?x='+Date.now(), {cache:'no-store'}).then(r => r.text())`. 결과가 길어 잘리면 `text.slice(0, 15000)`처럼 나눠 받아 이어 붙이고, 이어 붙인 길이가 `text.length`와 같은지 확인한다.
  - 페이지를 요약해서 돌려주는 웹 조회 도구는 쓰지 않는다. 전문을 건네야 하므로 한 글자도 달라지면 안 된다.
- 원문을 받을 수단이 없으면 거기서 멈추고 "브라우저 도구(Claude in Chrome 등)를 연결해야 진행할 수 있다"고 알린다.
- 응답이 404이거나, 내용이 `var 설정이름 = {...}` 형태의 설정 파일이 아니면 표준 스킨 몰이 아니다. "이 몰은 표준 스킨이 아니거나 setup.js가 없습니다. 개발팀에 문의하세요."로 끝낸다.

### 2. 요청에 해당하는 설정 찾기

- 파일 맨 위 머리 주석과 각 `var 이름 = ...` / `window.이름 = ...` 선언 위 주석을 읽는다. 주석에 "어느 화면에 보이나, 키마다 무엇을 적나, 비우면 어떻게 되나"가 적혀 있다.
- 요청한 화면 요소가 정말 그 설정에서 나오는지는 몰 페이지에서 확인한다. 화면에 보이는 문구를 `setup.js` 원문에서 검색해, 같은 문구가 들어 있는 전역을 찾는 것이 가장 빠르다.
- 키의 형식은 주석과 기존 값을 그대로 따른다. 색은 `"#RRGGBB"`, 링크는 기존 값과 같은 꼴(몰 내부면 `/`로 시작하는 경로), 배열 항목은 기존 항목과 같은 키 구성으로 쓴다. 주석에 경로 규칙(예: 이미지는 `/web/upload/…` 또는 전체 URL)이 있으면 지킨다.
- 이미지 교체 요청인데 새 이미지의 URL이 없으면, 먼저 이미지를 카페24에 올리고 그 주소를 달라고 요청한다. 임의 주소를 지어내지 않는다.

### 3. 세팅 위치 판단

요청을 아래 순서로 분류한다. 한 요청이 여러 곳에 걸치면(예: 짝 구매 전용 상품 추가 = setup.js + 훅 파일) 각각 처리하고 한 답변에 모은다. [references/admin-and-hook.md](references/admin-and-hook.md)의 "두 곳을 함께 고쳐야 하는 것"에 해당하면 다른 한쪽도 반드시 함께 안내한다.

**ⓐ 카페24 관리자 항목**: references 파일의 관리자 표에 있는 화면 항목이다. 상품 데이터(가격·소비자가·옵션·이미지·아이콘), 상품분류, 쿠폰, 배송비, 이용안내, 인기검색어, 사업자 정보가 여기에 속한다. 증상 질문("옵션변경 버튼이 안 보여요")은 "증상으로 찾는 관리자 설정" 표부터 본다.
- 노션 도구로 운영 매뉴얼을 열 수 있으면 해당 항목을 읽어 최신 경로를 확인한다. 열 수 없으면 references 파일의 요약을 쓴다.
- 미리보기는 하지 않는다. 관리자에 로그인하거나 대신 저장하지 않는다.

**ⓑ 훅 파일 항목**: 상세페이지 직접 접근 차단(짝 구매 전용 상품의 상세 진입 막기)이다. `setup.js`가 아니라 `hook/hook-detail-early.html`의 `window['상세차단상품설정']` 한 줄에서 고친다.
- 지금 목록은 몰의 상품 상세 페이지(`/product/detail.html?product_no=<아무 상품>`)에서 `window['상세차단상품설정']` 값을 읽어 확인한다. 브라우저 도구가 없으면 사용자에게 편집창에서 그 줄을 복사해 달라고 한다.
- 훅 파일은 URL로 받으면 카페24가 템플릿을 처리한 결과가 돌아와 원문과 다르다. 그래서 **전문을 만들지 않고, 바꿀 한 줄(변경 전 → 변경 후)만** 건넨다. 그 줄 아래의 스크립트는 건드리지 말라고 함께 안내한다.

**ⓒ setup.js 항목 (진행한다)**
- 1~2단계에서 찾은 전역에 해당하고, 아래 조건을 만족해야 한다.
- 이미 있는 전역의, 주석이나 기존 값에 이미 있는 키의 값을 바꾼다. 문구, 색, 링크, 이미지 주소, 상품번호, 켜고 끄기(`true`/`false`) 등이다.
- 배열 설정에 항목을 추가·삭제하거나 순서를 바꾼다. 단 기존 항목과 같은 키 구성이어야 한다.
- 주석이 "비우면 숨긴다"고 설명한 값을 비워서 숨긴다.

**ⓓ 그 외 ("개발팀에 문의하세요."로 끝낸다)**
- 요청한 화면 요소가 `setup.js`에도, 관리자 표에도, 훅 파일 항목에도 없다. 다른 스킨 파일이나 앱에서 나오는 화면이다.
- 주석에도 기존 값에도 없는 새 키·새 전역이 필요하다. 예) 주석에 없는 "글자 크기" 키를 넣어 크기를 바꾸기. 넣어도 읽는 코드가 없어서 아무 일도 일어나지 않는다.
- 배치, 크기, 여백, 동작, 노출 조건처럼 값이 아니라 화면 구조나 로직을 바꿔야 한다.
- 주석이 개발팀 관리, 인프라(데이터 공급 URL, API 주소, 주문 데이터 규격), 임시·가설검증이라고 밝힌 전역을 바꾼다.
- 미리보기에서 값은 바뀌었는데 화면이 요청대로 나오지 않는다(5단계). 그 설정만으로는 안 되는 요청이다.

요청에 ⓓ가 섞여 있으면 ⓐ~ⓒ 부분만 진행하고, 나머지는 "이 부분은 개발팀에 문의하세요."라고 따로 적는다. 4~5단계는 ⓒ setup.js 항목이 있을 때만 한다.

### 4. 수정 내용 만들기

- 수정은 **"원문에서 정확히 한 번 나오는 조각 → 바꿀 조각"** 쌍으로 만든다. 들여쓰기와 따옴표까지 원문 그대로 복사해 조각을 만든다. 같은 조각이 두 번 이상 나오면 앞뒤 줄을 더 붙여 한 번만 나오게 한다.
- 바꾸려는 값 외에는 한 글자도 건드리지 않는다. 주석, 공백, 다른 설정의 순서를 정리하지 않는다.
- 문구 안에 따옴표가 필요하면 작은따옴표(`'`)로 바꿔 쓴다(운영 매뉴얼 규칙). 사용자가 준 문구에 둥근 따옴표(`“ ”`)가 섞여 있으면 문자열을 감싸는 데 쓰지 않는다. 문구 중간 줄바꿈은 `\n`으로 쓴다. 배열·오브젝트의 쉼표를 빠뜨리지 않는다. 문법이 하나라도 틀리면 **이 파일의 모든 설정이 죽어** 헤더, 배너, 메인 전체가 기본값이나 빈 화면이 된다.
- 셸이 있으면 수정 쌍을 스크립트로 적용해 `setup.modified.js`를 만들고 `node --check setup.modified.js`로 문법을 확인한다. `diff`로 의도한 줄만 바뀌었는지도 본다.

### 5. 저장 전 미리보기

브라우저 도구가 있으면 반드시 한다. 요청한 화면이 나오는 몰 페이지(띠배너면 메인, 상세 설정이면 상품 상세)를 연 탭에서 아래 함수를 실행한다. 이 함수는 라이브 `setup.js`를 다시 받아 수정 쌍을 적용하고, 문법을 검사하고, 페이지 HTML의 `setup.js` 로더 바로 뒤에 수정본을 끼운 뒤 문서를 다시 그린다. 수정본이 같은 이름의 전역을 덮어쓰므로, 페이지의 모든 컴포넌트가 수정된 값으로 처음부터 렌더된다.

```js
async () => {
  const EDITS = [
    // 4단계에서 만든 쌍. old는 원문에서 정확히 한 번 나와야 한다.
    { old: 'bgColor: "#000000",', new: 'bgColor: "#2E7D32",' }
  ];
  const skin = location.pathname.match(/^\/(skin-[^/]+)\//);
  const setupUrl = (skin ? '/' + skin[1] : '') + '/setup.js?x=' + Date.now();
  let src = await (await fetch(setupUrl, { cache: 'no-store' })).text();
  for (const e of EDITS) {
    const n = src.split(e.old).length - 1;
    if (n !== 1) return { ok: false, reason: 'old 조각이 ' + n + '번 나옴', old: e.old };
    src = src.replace(e.old, () => e.new);
  }
  try { new Function(src); } catch (err) { return { ok: false, reason: '문법 오류: ' + err.message }; }
  let html = await (await fetch(location.href, { credentials: 'include', cache: 'no-store' })).text();
  const at = html.indexOf('/setup.js');
  if (at < 0) return { ok: false, reason: '페이지에 setup.js 로더가 없음' };
  const end = html.indexOf('</script>', at);
  if (end < 0) return { ok: false, reason: '로더 script 닫는 태그를 못 찾음' };
  const cut = end + '</script>'.length;
  const inline = '<script data-setup-preview>' + src.replace(/<\/script/gi, '<\\/script') + '\n</script>';
  html = html.slice(0, cut) + inline + html.slice(cut);
  document.open(); document.write(html); document.close();
  return { ok: true };
}
```

- `ok:false`가 나오면 이유를 보고 4단계로 돌아가 수정 쌍을 고친다. 문법 오류인 채로 전문을 건네지 않는다.
- `ok:true`가 나오면 2~3초 기다린 뒤 확인한다. ① `window.<전역이름>`의 값이 바뀌었는지, ② `document.querySelector('script[data-setup-preview]')`가 있는지, ③ 화면에서 요청한 요소가 요청대로 바뀌었는지 스크린샷이나 DOM 텍스트·계산된 스타일로 본다. 값은 바뀌었는데 화면이 그대로면 3단계 ⓓ의 마지막 항목에 해당한다.
- 화면 상태에 따라 안 보이는 설정이 있다. 주석에 "모바일(1024px 이하)에서만", "비회원에게만"처럼 조건이 있으면 그 조건을 맞춘 화면에서 본다. 뷰포트를 바꾸는 기능(emulate)이 있으면 쓰고, 없으면 "PC 화면에서는 미리보기가 보이지 않는 항목이라 반영 후 휴대폰에서 확인해 달라"고 알린다. "오늘 하루 보지 않기"로 닫혀 있던 배너도 안 보일 수 있다.
- 미리보기는 그 탭의 그 페이지에만 있다. 새로고침하거나 다른 페이지로 가면 사라진다. 다른 페이지에서도 봐야 하면 그 페이지로 이동한 뒤 함수를 다시 실행한다.
- 미리보기 탭은 닫지 않고 그대로 둔다. 사용자가 직접 확인한다.

브라우저 도구가 없으면 미리보기를 건너뛰고, 보고에 "미리보기를 하지 못했다(브라우저 도구 없음)"고 분명히 적는다.

### 6. 전달

독자는 비개발자다. 코드 용어 대신 "화면 어디 → 어디서 세팅"으로 설명한다. 3단계 분류마다 아래 형식으로 쓰고, 여러 곳에 걸치면 한 답변에 차례로 모은다.

**ⓒ setup.js 항목**: 아래 다섯 가지를 모두 담는다.

1. **바꿀 곳**: 설정 이름(예: `상단띠배너설정`)과 키, 파일 안에서 찾는 법(편집창에서 `var 상단띠배너설정` 검색). 변경 전 조각과 변경 후 조각을 나란히 보여준다.
2. **미리보기 결과**: 무엇을 어느 화면에서 확인했는지, 확인하지 못한 화면 조건(모바일 전용, 비회원 전용 등)이 있으면 그 내용.
3. **변경 후 전문**: 원문에 수정을 적용한 `setup.js` **파일 전체**. 사용자는 편집창 내용을 전부 지우고 통째로 붙여넣는다. 조각이나 "이 줄만 바꾸세요"로 대신하지 않는다.
   - 파일을 쓸 수 있으면 `setup.js`로 저장하고 경로를 알려준다. 채팅에도 코드블록 하나로 전문을 함께 싣는다.
   - 전문은 반드시 기계적으로 만든다(셸 스크립트로 적용하거나 브라우저에서 `src.replace` 결과를 받는다). 원문을 눈으로 옮겨 적지 않는다. 한 글자 실수가 전 설정을 죽인다.
   - 셸·파일 도구가 없으면, 미리보기 함수와 같은 방식으로 수정본 `src`를 만든 뒤 브라우저에서 파일로 내려받게 한다: `const a = document.createElement('a'); a.href = URL.createObjectURL(new Blob([src], {type: 'text/javascript'})); a.download = 'setup.js'; document.body.appendChild(a); a.click();`. 사용자에게 다운로드 폴더의 `setup.js`를 열어 통째로 복사하라고 안내한다. 채팅의 코드블록은 참고용이라고 밝힌다.
4. **반영 방법**: 카페24 관리자 → 디자인(PC/모바일) → 디자인 보관함에서 해당 스킨의 "편집" → 스마트디자인 편집창 파일 목록에서 `setup.js` → 전부 지우고 전문 붙여넣기 → 저장. 반영 뒤 몰 화면을 새로고침해 확인한다. 실제 운영 스킨에 바로 저장하기 전에 가능하면 개발 스킨에서 먼저 확인하라고 덧붙인다.
5. **범위 밖 항목**: 있었으면 "이 부분은 개발팀에 문의하세요."와 이유 한 줄.

**ⓐ 관리자 항목**
- 세팅 위치: "카페24 관리자 > … > …" 메뉴 경로
- 세팅 방법: 무엇을 어떻게 바꾸는지와 주의사항(예: 저장 즉시 운영 반영, '표시함'이어야 보임)
- 출처: 운영 매뉴얼 링크 `https://app.notion.com/p/3c208b93608a8048976ce886b45c61fe`와 해당 항목 제목

**ⓑ 훅 파일 항목**
- 파일: 스마트디자인 편집창 → setup.js가 있는 스킨 폴더 → `hook/hook-detail-early.html`
- 변경 전 한 줄과 변경 후 한 줄(`window['상세차단상품설정'] = [...]`). 대괄호 안 상품번호만 바꾸고 그 아래 스크립트는 건드리지 말 것
- 확인 방법: 저장 후 차단한 상품의 상세 URL을 열면 메인으로 이동해야 한다
- 구매까지 막아야 하면 관리자에서 판매 상태를 따로 바꿔야 한다는 안내

**ⓓ 그 외**: 이유 한 줄과 **"개발팀에 문의하세요."** 만 답한다.

## 자주 하는 실수

| 실수 | 결과 |
|---|---|
| 몰 URL 없이 추측한 몰로 진행 | 다른 몰의 setup.js를 고쳐 건넨다. URL이 없으면 묻고 끝낸다 |
| 요약형 웹 조회로 원문을 받음 | 전문이 원본과 달라져 붙여넣는 순간 다른 설정이 깨진다 |
| 주석에 없는 키를 넣어 "될 것"이라고 안내 | 읽는 코드가 없어 아무 변화가 없다. 범위 밖으로 판단해 개발팀 문의로 끝낸다 |
| 미리보기 없이 전문만 건넴 | 문법 오류나 엉뚱한 설정 수정이 저장 후에야 드러난다 |
| 전문을 손으로 옮겨 적음 | 따옴표·쉼표 하나 차이로 모든 설정이 죽는다. 기계적으로 만든다 |
| 관리자 항목을 "개발팀에 문의하세요"로 끝냄 | 사업부가 직접 할 수 있는 일을 막는다. 관리자 표부터 확인하고 경로를 안내한다 |
| 짝 구매 전용 상품 작업에서 한쪽만 안내 | `추가구성짝설정`과 `상세차단상품설정` 중 하나만 바뀌어 주문과 상세 진입이 어긋난다 |
| 훅 파일 전문을 URL로 받아 건넴 | 받은 내용은 카페24가 처리한 결과라 원문과 다르다. 붙여넣으면 훅이 깨진다. 한 줄만 안내한다 |
| 범위 밖 요청에 다른 파일 수정안이나 코드를 제시 | 이 스킬의 범위를 넘는다. "개발팀에 문의하세요."로 끝낸다 |
| 관리자 편집창 저장을 대신 하거나 제안 | 하드 경계 침범. 반영은 사용자가 한다 |
| 미리보기 후 새로고침해서 "최종 확인" | 미리보기가 사라지고 반영 전 원본이 보여 판단이 꼬인다 |
