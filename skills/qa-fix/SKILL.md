# qa-fix — QA 수정요청 문서를 받아 완주하기

디자이너·기획자가 노션(또는 슬랙)에 남긴 QA 수정사항을 받아 **분석 → 수정 → 라이브 검증 → 태스크별 커밋**까지 한 번에 처리하는 워크플로. 문서는 보통 "스크린샷 + 번호 박스 + 번호별 요청 목록" 형태다.

## 0. 입력 확보

- **노션 링크**: Notion MCP의 fetch 도구로 페이지를 읽는다. 본문의 체크리스트가 태스크 목록이다.
- **슬랙 링크**: Slack 스레드/메시지 읽기 도구로 확보한다.
- 링크 없이 텍스트+이미지를 직접 붙여줬으면 그대로 사용한다.

## 1. 이미지를 반드시 눈으로 확인한다

태스크의 번호는 **이미지에 그려진 번호 박스**를 가리킨다. 텍스트만 읽으면 "옵션선택"이 드로어 헤더인지 옵션 아코디언 제목인지 구분할 수 없다 — 같은 문구가 화면에 여러 번 나오는 게 보통이라, 이미지 확인 없이 추측하면 엉뚱한 요소를 고치게 된다.

- 노션 본문의 이미지 URL(S3 presigned)을 curl로 스크래치패드에 내려받아 Read로 열어본다. presigned URL은 만료가 있으니 fetch 직후 바로 받는다.
- 각 번호 박스가 감싼 영역 = 그 태스크의 대상 요소. 번호↔영역 매핑을 먼저 정리하고 나서 코드를 찾는다.

## 2. 요청 문구의 관례 읽기

QA 작성자가 쓰는 괄호 주석은 적용 범위 지시다. 놓치면 절반만 고친 게 된다:

- **"(Mobile도 적용)"** — 같은 UI의 모바일 형상에도 적용. 반응형 하나의 마크업이면 미디어쿼리/상태클래스 양쪽을 확인한다.
- **"(상세페이지도 적용)" / "(~페이지도 적용)"** — 같은 컴포넌트가 쓰이는 다른 지면에도 적용. 컴포넌트가 공유되면 한 번의 수정으로 커버되는지, 지면별 오버라이드가 있는지 확인한다.
- 괄호가 없어도 사용자가 대화에서 범위를 지정했으면(예: "상세페이지도 적용이라고 써있는 건 X에도 적용하란 뜻") 그걸 따른다.
- 요청 값이 구체적(px, font-weight 수치 등)이면 그대로 반영하되, 프로젝트가 디자인 토큰을 쓰면 **수치에 대응하는 토큰**으로 치환한다(예: 600 → `var(--std-font-weight-semibold)`).

## 3. 소유 파일 역추적

번호가 가리키는 UI 영역에서 출발해 실제 스타일/마크업을 소유한 파일을 찾는다.

- 프로젝트의 아키텍처 문서·컴포넌트 헤더 주석을 먼저 읽는다 — "이 UI는 어느 컴포넌트 소관"이 주석에 적혀 있는 경우가 많다(예: 드로어 셸은 껍데기만, 내부 UI는 iframe 문서 소관).
- 같은 화면이라도 요소마다 소유자가 다를 수 있다(페이지 사이드카 CSS vs 공유 컴포넌트 CSS). 태스크별로 각각 확인한다.
- 증상이 "스타일이 안 먹음"류면 특이성/오버라이드 충돌을 의심하고 computed 스타일로 원인 규칙을 먼저 확정한 뒤 고친다 — 이기는 규칙을 모른 채 값만 바꾸면 재발한다.

## 4. 피그마 링크가 있으면

QA 문서나 태스크에 피그마 링크가 첨부돼 있으면 **구현 전에** 해당 노드를 읽고 수치·구조를 시안 기준으로 잡는다. 피그마 구현에는 figma 플러그인의 design-to-code 스킬 절차를 따른다(get_design_context 호출 전 해당 스킬 로드가 필수).

## 5. 수정

- 프로젝트의 코딩 규칙(CLAUDE.md, .claude/rules/)을 따른다.
- 태스크 단위로 외과적으로 — 한 태스크의 diff에 다른 태스크나 무관한 정리를 섞지 않는다(커밋을 태스크별로 쪼개기 위해서이기도 하다).
- 수정한 값이 주석·문서에 상수로 언급돼 있으면(예: "base gap(16px)이 …") 그 언급도 함께 동기화한다.

## 6. 라이브 검증

수정을 배포/업로드한 뒤 실제 화면에서 확인한다. 검증 없이 "됐다"고 보고하지 않는다.

- 브라우저 검증은 프로젝트 공통 규칙을 따른다(공유 디버깅 크롬 attach, 내 탭에서만 작업, 뷰포트는 emulate만).
- 캐시로 구버전이 섞여 나올 수 있는 환경(카페24 등)이면 fresh 쿼리 파람으로 최신 렌더를 확보하고 판정한다.
- 값 검증은 스크린샷 눈대중보다 **computed 스타일/rect 측정 스크립트**가 정확하다 — gap·폭·font-weight는 스크립트로 수치를 찍고, 전체 인상은 스크린샷으로 이중 확인한다.
- "(Mobile도 적용)" 태스크는 모바일 에뮬레이션으로도 확인한다.
- 로그인 상태 등 재현이 어려운 조건은 DOM에서 상태 클래스를 토글해 시뮬레이션하되, **확인 후 원복**하고, 최종 보고에 "실제 조건에서 한 번 확인 권장"을 명시한다.
- 검증에 연 탭은 끝나면 닫는다.

## 7. 태스크마다 커밋

- **태스크(번호) 단위로 커밋한다.** 한 태스크 = 수정 + 검증 + 커밋 한 사이클. 여러 태스크가 같은 줄을 건드려 분리가 무의미할 때만 묶고, 커밋 메시지에 항목을 나열한다.
- 커밋 메시지는 프로젝트 관례를 따르고, 본문에 무엇을 왜(원인 포함) 바꿨는지 남긴다.

## 8. 보고

QA 항목 번호별로: 무엇을 어떻게 고쳤는지(원인이 비자명했으면 원인 포함), 검증 결과(측정값), 커밋 해시. 시뮬레이션으로 검증한 항목은 그 사실과 후속 확인 권장을 덧붙인다.
