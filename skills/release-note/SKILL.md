# Release Note → Slack

이번 세션에서 한 작업을 짧은 릴리즈노트로 정리해 슬랙 채널 `#2_pjt_cafe24-release-note`에 보낸다. 읽는 사람은 팀 동료다 — 작업 배경을 모르는 사람이 "무슨 문제였고, 뭘 고쳤는지"를 한눈에 파악하는 게 목적이다.

## 전제

- 커밋과 푸시는 **사용자가 직접** 한다. 이 스킬은 절대 커밋/푸시를 대신 하지 않는다.
- 요약 재료는 현재 세션의 대화 컨텍스트다(요청 내용, 원인, 수정한 파일). 별도 조사가 필요 없는 게 정상이며, 세션에서 이미 아는 내용을 다시 탐색하지 말 것.

## 절차

### 1. 이번 세션의 커밋 수집

```bash
git log origin/main..HEAD --oneline   # 미푸시 커밋 확인
git log -5 --format='%H %s'           # 최근 커밋에서 이번 세션 작업분 식별
```

- 이번 세션에서 작업한 내용에 해당하는 커밋(들)을 식별한다. 커밋 메시지와 세션에서 수정한 파일을 대조하면 된다.
- **미푸시 커밋이 릴리즈노트 대상에 포함되어 있으면 멈추고 사용자에게 푸시를 요청한다.** 커밋 URL은 푸시 전엔 404다. 푸시도 사용자가 한다 — 대신 실행하지 말 것.
- 세션 작업분인데 아직 커밋이 안 된 변경이 있으면(git status로 확인) 그것도 알리고, 사용자가 커밋·푸시할 때까지 대기한다.
- 커밋 URL 형식: `https://github.com/egnis-it/ftp-cafe24/commit/<sha>` (전체 sha 사용)

### 2. 메시지 작성

형식 — 슬랙 PR 코멘트 느낌으로 간결하게:

```
*[몰명] 작업 제목 한 줄*
문제/요청 설명과 어디를 어떻게 고쳤는지 한두 문장.
<커밋URL|커밋메시지 또는 짧은 설명>
```

- 몰명은 클룹/한끼통살/랩노쉬 등 실제 몰 이름으로.
- 설명은 한두 문장을 넘기지 말 것. 파일 경로는 핵심 파일 1~2개만, 전체 나열 금지.
- 커밋이 여러 개면 커밋 링크를 줄바꿈으로 나열한다.
- 세션에 요청 노션 링크가 있으면 마지막 줄에 `<노션URL|요청 노션>` 으로 덧붙인다.
- 슬랙 mrkdwn 문법 사용: 링크는 `<url|텍스트>`, 굵게는 `*텍스트*`.

**예시:**

```
*[클룹] 오프아워 상품 한정 배송문구 수정*
오프아워 상품 상세에 일반 배송문구가 노출되던 문제. product/detail.html의 배송안내 분기 조건을 수정해 오프아워 전용 문구가 뜨도록 함.
<https://github.com/egnis-it/ftp-cafe24/commit/b90739d...|fix: 오프아워 상품 한정 배송문구 수정>
<https://notion.so/...|요청 노션>
```

### 3. 미리보기 → 확인 → 전송

1. 완성된 메시지를 사용자에게 보여주고 확인받는다. **확인 없이 바로 보내지 말 것** — 외부 채널이다.
2. 사용자가 승인하면 슬랙 MCP 도구(`slack_send_message`)로 `#2_pjt_cafe24-release-note` 채널에 전송한다. 도구 스키마가 로드되어 있지 않으면 ToolSearch로 `select:mcp__plugin_slack_slack__slack_send_message`를 먼저 로드한다.
3. 전송 후 결과(성공 여부)를 사용자에게 알린다.

수정 요청이 오면 반영해서 다시 미리보기부터.
