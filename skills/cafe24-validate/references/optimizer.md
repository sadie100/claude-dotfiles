# Cafe24 HTML 옵티마이저 — @js/@css 번들링 (이 스킬이 잡는 사고의 원리)

> 정본은 standard-cafe24 레포의 `CLAUDE.md` "HTML Optimizer" 절과 `knowledge/cafe24-optimizer-bundling.md`·`knowledge/cafe24-optimizer-official-guide.md`(카페24 공식 가이드 대조). 이 파일은 글로벌 스킬이 레포 없이도 동작하도록 둔 요약본이다(2026-10-22 정본 기준으로 갱신). 상충하면 프로젝트 문서가 우선.

카페24는 페이지를 서버 렌더(레이아웃 병합 → 치환변수/모듈 해석)한 뒤 문서 곳곳의 `<!--@js(...)-->`/`<!--@css(...)-->`를 수거해 번들로 합친다. 옵티마이저를 끄는 몰 설정은 없는 것으로 본다.

- **번들 위치**: CSS 번들은 `<head>` 끝(렌더블로킹), JS 번들은 문서 하단(기본 `</body>` 직전). 두 계열이 있다 — `optimizer.php`(카페24 자체, 먼저) → `optimizer_user.php`(스킨 파일, URL 에 `user=T`). 그래서 첫 페인트 전에 돌아야 하는 코드는 `@js`로 불가능하다.
- **같은 슬롯 안의 수집 순서는 HTML 등장 순서가 아니라 본문 페이지 파일 → 레이아웃 파일 → import 파일**이다(공식 가이드, 2026-10-22 실측 일치). 같은 파일 안의 `@js` 순서는 유지되지만, 레이아웃 head 에 쓴 스크립트가 페이지 body 의 것보다 뒤에 실행될 수 있는 이유다.
- 같은 파일을 레이아웃·페이지 양쪽에 선언하면 dedupe되며 **페이지 쪽(앞) 자리가 우선**.
- `<!--@jsTop(경로)-->`로 선언한 파일은 스킨 JS 번들 맨 앞에서 돈다(import 파일에 써도). 그래도 카페24 자체 번들 뒤·문서 하단이다.
- 근본 안전 패턴: **전역값을 로드 시점에 캡처하지 말고 사용 시점에 window에서 읽기(lazy).** `var CONFIG = window.X || {}` 같은 즉시 캡처는 선언 순서가 바뀌면 빈 값으로 굳는다.
- 존재하지 않는 파일의 `@js`/`@css`는 **에러 없이 번들에서 조용히 빠진다** — 기능이 통째로 안 나오면 파일 404부터 의심.
- 한 파일의 최상위 throw 는 같은 번들에서 그 뒤에 합쳐진 파일을 전부 죽인다 — "앞 컴포넌트 부분 동작 + 뒤 컴포넌트 전멸"이 시그니처.
- `@css` 선언 하나를 더하거나 옮기면 번들 안 CSS 파일 순서가 바뀌어, 특이도가 같은 규칙끼리의 승부가 뒤집힐 수 있다 — "아무것도 안 바꾼 섹션이 다른 컴포넌트 추가 뒤 깨짐"이 시그니처.

## 왜 이게 이 스킬의 존재 이유인가

선언 순서 역전으로 빈 값이 캡처되면 JS가 **throw 없이 조용히 실패**한다. 결과:

- **콘솔 에러 없음** → 콘솔 모니터링으로 못 잡음.
- **DOM(HTML) 구조 동일** (스타일만 안 먹음) → DOM diff로 못 잡음.
- 그 배포에선 **결정론적으로 깨진 상태** → 스크린샷 1장으로 재현됨.

→ 손 안 댄(unworked) 페이지를 **라이브와 스크린샷 비교**하는 것만이 이 클래스를 탐지한다.

## 검증 시 주의

- 페이지 소스에서 스크립트 파일명 검색해도 안 나오는 게 정상 — 개별 `<script src>`가 아니라 번들 안에 합쳐져 있다. 번들 응답 내용에서 코드 존재·offset으로 확인. 번들 URL 의 `filename=`(urlsafe-base64 + raw DEFLATE)을 디코드하면 합쳐진 원본 파일 목록과 순서가 나온다.
- 각 스킨 파일은 번들과 별개로 자기 URL 에서 원본 그대로 서빙된다. 단 번들은 JS 문자열 속 루트 상대 경로에 스킨 프리픽스(`/skin-skinN`)를 덧붙여 리라이트하므로, 경로 리터럴이 개별 파일과 번들에서 다른 건 정상이다 — 번들 신선도는 방금 넣은 다른 마커(새 주석 등)로 판단한다.
- 압축은 CSS 번들만 된다(한 줄, 주석 없음). JS 번들은 줄바꿈·주석이 그대로다(2026-10-22, 5개 몰). CSS 번들에 `grep -c` 를 쓰면 줄 수(1)가 나오니 `grep -o | wc -l` 로 센다.
- **업로드 반영은 페이지가 실제로 불러오고 실행한 것으로 판정한다.** 실제 상세 페이지가 업로드 뒤에도 옛 번들을 참조·실행한 반례가 있어서, 개별 파일 해시나 새 쿼리 응답만으로는 부족하다. 서빙된 HTML 이 가리키는 번들 URL(`t=`·`filename=` 디코드), 그 번들 본문, computed 값이나 실행 계측을 함께 본다. 측정·반례·우회는 standard-cafe24 레포 `knowledge/cafe24-upload-html-bundle-set-switch.md` 한 곳에 있다.
- 서버는 User-Agent 로 PC/모바일 렌더 모드를 고르고 두 모드가 템플릿 변수를 다르게 채운다. MO 검증은 뷰포트만 줄이지 말고 모바일 UA 로 한다.
- **전역 설정값이 콘솔엔 찍히는데 UI가 안 나오면** "로드 안 됨"이 아니라 "실행 순서 역전으로 빈 값 캡처"를 의심.
